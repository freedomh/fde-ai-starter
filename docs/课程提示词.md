# 直接复制的课堂提示词

使用方法：在 AI 编码工具里打开克隆目录，按顺序发送。每轮跑通再进入下一轮。新会话先让 AI 读取 README.md、AGENTS.md 和本文件；不依赖上一段聊天的记忆。

## 01 空电脑准备

```text
我是零基础，使用 Windows。这台电脑还没有开发环境。
请先检查 Git、Docker Desktop、Docker 引擎、Compose、WSL 2 和 Linux 容器模式。
我采用 Vue 3 + TypeScript、Java 17 + Spring Boot、MySQL、Redis、Docker Compose。
优先用容器构建运行，不要求我在 Windows 全局安装 Node、JDK、Maven 或数据库。
缺什么就按官方说明一步步引导安装；需要管理员、BIOS、同意协议或重启时明确告诉我操作什么，不替我绕过。
完成后实际运行 git --version、docker version、docker compose version、docker info。
告诉我环境是否可用、还缺哪项；不要把“已经安装”当成“引擎已经运行”。
```

## 02 克隆空架子并全量跑通

```text
请将 https://github.com/freedomh/fde-ai-starter.git 克隆到一个新的 my-ai-project 目录，不覆盖已有目录。
进入工程先读 README.md 和 AGENTS.md，保留 frontend、admin、backend、infra 的结构。
运行 Start-Local.ps1，用 Docker 同时构建并启动前端、管理端、Java、MySQL、Redis。
缺少软件或引擎未就绪时先定位环境缺项，不改业务代码掩盖错误。
检查两个页面以及 /api/health，确认 Java、MySQL、Redis 都是 UP。
出错时先解释第一条关键报错，最小修复并重新执行；不要跳过测试，不删除数据卷，不影响其他项目。
最后给我实际访问地址、真实执行结果和仍未通过的项。本轮不做业务功能。
```

## 03 实际项目：课程反馈台需求

```text
在当前已经跑通的骨架上，实现本地单人“课程反馈台”，只用虚构学员数据。
管理端可以新增学员、记录授课主题/课堂表现/课后任务、生成反馈草稿、编辑并确认。
学员端选择演示学员后，只能看到已确认反馈；草稿不出现在学员端。
草稿先用本地文本模板生成，不调用外部模型，不需要任何模型 API Key；生成结果必须标为本地模板。
同一条课堂记录只能有一份反馈，重复生成/确认不能重复创建；确认后不能继续编辑。
MySQL 保存正式记录，Redis 缓存统计 30 秒，写入提交后失效；缓存故障回退 MySQL。
先读现有工程，将以上写成 docs/需求与接口.md，列出数据表、接口、页面和可执行验收清单。本轮先完成设计，不改技术栈。
```

## 04 先实现后端

```text
使用当前 Java 17 + Spring Boot + JDBC + Flyway + MySQL + Redis，实现 docs/需求与接口.md。
新增 Flyway V2 创建学员、课堂记录、反馈三张表；保留已有 V1 和旧数据，不重新生成整个后端。
实现学员新增/列表、课堂记录新增/列表、生成或读取唯一草稿、编辑草稿、幂等确认、学员端已确认列表及统计。
后端校验必填和长度，找不到记录返回 404，确认后编辑返回 409；错误返回可读 message。
草稿用本地模板，不接外部 AI；课堂记录与反馈使用唯一关联，防止重复生成。
加入 Redis 统计缓存与写后失效；数据库为准，缓存故障不让成功写入变成失败。
补后端测试，尤其验证草稿不对学员端显示、重复确认、确认后禁止编辑和无效输入。
用 Docker Compose 构建 backend（构建内运行 mvn verify），实际启动并调用接口，修复到通过后报告结果。
```

## 05 再实现前台和管理端

```text
沿当前 Vue 3 + TypeScript 分别实现 frontend 和 admin，不把业务数据写死在页面里。
先读取 docs/需求与接口.md 和已实现的接口；所有请求使用相对 /api，集中在各端 src/api.ts。
管理端有学员新增、课堂记录表单、记录列表和反馈编辑区；生成草稿时显示“本地模板”，教师确认后只读。
学员端可选择虚构学员，显示已确认反馈；无反馈时给清楚的空状态，不显示草稿。
补齐加载、空状态、保存中禁重复点击、失败保留输入和成功提示，桌面/手机都可用。
两个前端都通过 Docker 内的 npm ci 与构建；不能靠假数组或仅截图证明联调成功。
实际完成一次“创建课堂记录→生成草稿→编辑→确认→学员端看到”的浏览器流程。
输出改动文件、执行命令和真实结果；如果某项没验证，明确写出来。
```

## 06 重建、联调和持久化验收

```text
请运行 Start-Local.ps1 重新构建并启动本项目所有服务，然后逐项验收：
1. 两个页面、Java、MySQL、Redis 可用；2. 创建一条虚构课堂记录并生成草稿。
3. 确认前学员端看不到；4. 编辑草稿并确认后，学员端显示相同内容。
5. 再次确认不产生第二份反馈；6. 已确认内容不能继续编辑，返回 409。
7. 统计缓存可读取且有 TTL，新增/确认后统计变化；8. 无效输入被拒绝且不写库。
保留命名卷执行 down/up 后，再核对同一条记录和状态仍在；不要使用 down -v。
把可重复检查写进 scripts/Verify-Demo.ps1；实际执行并修复，不只提供建议。
最后整理启动、访问、日志、停止和数据保留说明，列出已完成、已验证和未完成。
```

## 07 遇到报错直接发送

```text
请排查我在当前项目中的错误。目标、执行目录、完整命令、期望、实际结果和第一段完整报错如下：
【在这里粘贴实际信息；密码和个人资料先脱敏】
先查现有代码与配置，再提出最可能原因和只读检查命令，不凭猜测更换整套技术栈。
做最小修复后重跑原失败命令和相关测试，不关闭校验、不跳过测试、不清空 MySQL 卷、不影响其他项目。
需要我安装、重启或提供缺失信息时，明确说明具体原因和下一步操作。
最后用执行结果说明是否解决，不能只说“代码已修复”。
```

## 08 学员练习：增加下次跟进日期

```text
基于当前课程反馈台，给课堂记录增加 nextFollowUpDate，可选的下次跟进日期。
先列出 SQL 迁移、后端字段/API、管理端表单和学员端显示需要改哪些文件，本轮只写计划。
保留旧记录；新增 V3，不改已执行的 V1/V2；旧记录日期为 null。
后续实现必须验证未填写、合法日期、无效日期、旧记录兼容和重启后读取；只把已确认反馈展示给学员。
不要为了一个字段重写项目或引入新服务。给出清楚的任务与验收，再进入代码实现。
```

```text

先只做 GET /api/health，实际检查 MySQL 查询与 Redis PING；健康返回 200，不可用返回 503。

在 infra/compose.yaml 编排 backend/mysql/redis，数据库和缓存健康后再启动 Java；仅发布本机 API 端口。
提供 PowerShell 初始化/启动/停止脚本、README 和最小测试，停止保留 MySQL 数据卷。

```

```text
保留已经可运行的 backend 和 infra，在同级添加 frontend 与 admin 两个 Vue 3 + TypeScript + Vite 工程，生成依赖锁文件。
两端先只做骨架页面与 /api/health 连接显示；不加入业务、登录、支付或真实资料。

只绑定本机三个端口，MySQL/Redis 不暴露到公网；保留独立数据卷与随机本地配置。
更新启动脚本，一次构建运行五个服务；等待健康后打印两个页面与 API 的实际地址。
实际运行并检查两个页面和依赖连接，把可重复的命令和已验证结果写进 README。
```
