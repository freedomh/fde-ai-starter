# 课程反馈台：需求与接口

本地单人课堂演示，使用虚构信息；无登录和权限隔离。学员端、教师端只是两种页面入口，不能声称已经实现生产鉴权。API 不接外部模型；草稿由本地文本模板整理，教师编辑并确认后才出现在学员端列表。

## 数据

- demo_student：id、name、created_at；默认两个虚构学员。
- demo_lesson：id、student_id、topic、performance、homework、created_at。
- demo_feedback：id、唯一 lesson_id、content、status、created_at、confirmed_at。

迁移 V1 为技术标记，V2 新建业务表与虚构学员。后续字段变化新增 V3，不修改已执行迁移。

## 状态与约束

同一课堂记录至多一份反馈。生成重复请求返回同一条；DRAFT 允许编辑，CONFIRMED 只读；重复确认返回同一份已确认反馈。学员端接口在 SQL 查询里筛选 CONFIRMED，不靠前端隐藏草稿。

输入由后端校验：姓名非空且最多 40 字；主题非空且最多 100；课堂表现非空且最多 2000；课后任务可选且最多 1000；反馈内容非空且最多 4000。无效请求 400，不存在记录 404，已确认后编辑 409。错误返回可读 message，不返回堆栈或凭据。

## API

| 方法 | 路径 | 输入 / 结果 |
|---|---|---|
| GET | /api/health | MySQL 查询、Redis PING；200 UP 或 503 DOWN |
| GET / POST | /api/students | 数组 / {name}，新增返回 201 |
| GET / POST | /api/lessons | 数组 / {studentId,topic,performance,homework}，新增 201 |
| GET | /api/feedback | 教师端反馈数组，含 DRAFT/CONFIRMED |
| POST | /api/lessons/{id}/feedback | 本地模板创建草稿或返回已有反馈 |
| PUT | /api/feedback/{id} | {content}，只更新 DRAFT |
| POST | /api/feedback/{id}/confirm | 确认，重复请求幂等 |
| GET | /api/students/{id}/feedback | 仅该虚构学员的 CONFIRMED 反馈 |
| GET | /api/stats | {students,lessons,drafts,confirmed} |

统计缓存 key=fde:class-feedback:stats，TTL 30 秒。正式数据保存在 MySQL；数据库提交后失效旧统计缓存，Redis 故障回退数据库。简单缓存存在并发短时陈旧窗口，不保证强一致。

## 验收

新增课堂记录→生成草稿→学员端仍为空→教师编辑保存确认→学员端看到相同内容。重复生成/确认不重复创建；确认后编辑 409；空白输入 400 且不入库；未知 id 404；统计随新增与确认变化；保留卷重建容器后记录及状态仍在。
